Prereqs — install once per machine

  1. Git for Windows — git-scm.com/download/win. During install, tick "Git from the command line and also from 3rd-party software" so PowerShell finds it.
  2. uv — in PowerShell: 
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
    Fallback if the installer can't reach astral.sh: pip install uv. Close and reopen PowerShell after.
  3. PostgreSQL — same major version as source. postgresql.org. Note the postgres superuser password during install.
  4. GitHub auth — the env-repo is private, so this is required. Easiest: install GitHub CLI and run gh auth login. Or set up an SSH key on this machine and add it to your GitHub account.
  5. Chrome + tv_bridge — only if the TradingView bridge is used. Load unpacked from tv_bridge/ in this repo via chrome://extensions (Developer mode on).

First-time deploy

Run from PowerShell. Each block is one logical step.

Step 1 — Folder layout
mkdir C:\codebase\prod
mkdir C:\codebase\env-repo
Step 2 — Clone the app

Replace v0.1.0 with the tag you want to deploy (see git tag --list on the source, or the GitHub Releases page).

cd C:\codebase\prod
git clone https://github.com/TeroMeht/32_smsystem.git
cd 32_smsystem
git checkout v0.1.0
Step 3 — Clone the env-repo

Replace the URL with your actual env-repo URL.

cd C:\codebase\env-repo
git clone https://github.com/TeroMeht/env-repo.git
Step 4 — Create the venv and install dependencies

uv installs Python 3.13 if needed, creates .venv\, resolves every pinned package, and clones data_sources + indicators from GitHub at their pinned commits.

cd C:\codebase\prod\32_smsystem
uv python install 3.13
uv venv --python 3.13
uv pip install -r requirements.txt
Step 5 — Set up PostgreSQL

1. pgadmin create database 32_smsystem

2. run schema.sql

Step 5.5 — Run stock universe script
cd C:\codebase\prod\32_smsystem
.\.venv\Scripts\python.exe -m backend.stock_universe.run
Step 6 — Smoke test
uv run python -c "import data_sources, indicators, backend; print('OK')"
uv run pytest tests\
.\start.bat

Open http://127.0.0.1:8001 in a browser. If it works, continue.

Desktop shortcut

In Explorer: right-click desktop → New → Shortcut → target C:\codebase\prod\32_smsystem\start.bat → name it "Start SM System". Optionally right-click → Properties → Change Icon.

Redeploy — pulling updates

For any subsequent update (new commit, new tag, new env value):

cd C:\codebase\prod\32_smsystem
.\deploy.ps1

That script pulls the env-repo, pulls the app repo, and re-runs uv pip install -r requirements.txt so any dependency changes get picked up. Then double-click the desktop shortcut to relaunch.

To move to a specific tag instead of main's tip:

cd C:\codebase\prod\32_smsystem
git fetch --tags
git checkout v0.2.0
uv pip install -r requirements.txt

Install the Chrome TradingView bridge

Optional. Only needed if you use the ↗ TradingView buttons on the /relatr dashboard. The extension routes every click into a single reused TradingView tab instead of stacking new ones. Without it the buttons still work — they just don't reliably reuse the tab (COOP severs plain window.open named-target reuse).

Step 1 — Open Chrome extensions

In Chrome, go to chrome://extensions. Toggle Developer mode on (top-right).

Step 2 — Load unpacked

Click Load unpacked (top-left) and select the folder C:\codebase\prod\32_smsystem\tv_bridge (the folder that contains manifest.json — not the file itself, and not the repo root).

A card titled "SM System — TradingView Bridge" (version 1.0.0) should appear. Make sure its toggle is on.

Step 3 — Verify
  1. Start the app via the desktop shortcut and wait for http://127.0.0.1:8001 to come up.
  2. Open http://127.0.0.1:8001/relatr in Chrome (must be Chrome — the manifest uses Chrome's extension API).
  3. Click any ↗ button in a row. First click opens a new TradingView tab; every subsequent click should reuse that same tab and bring it to the front.
After editing any file under tv_bridge\, hit the reload (⟳) button on the extension card at chrome://extensions — Chrome does not auto-reload unpacked extensions. Then refresh the /relatr page so the new content.js attaches.

Debugging

SymptomWhere to look
Clicks still stack new TradingView tabsExtension card at chrome://extensions → Inspect views: service worker. Any [tv_bridge] failed to route … errors land in that console.
Clicks aren't intercepted at allOpen DevTools on the /relatr page (F12) → Console. If content.js didn't load, confirm the URL is http://127.0.0.1:8001/... (matches the manifest) and not a different host/port.
Backend port changedUpdate host_permissions and content_scripts.matches in tv_bridge\manifest.json, commit, then reload the extension on each target machine.
